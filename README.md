# Student Profile — คู่มือติดตั้ง
ระบบส่งรูปภาพ ชื่อเล่น เบอร์โทรศัพท์ และรายงานรายห้องสำหรับ GitHub Pages + Supabase

## 1. สร้าง Supabase project
1. เปิด https://supabase.com/dashboard สร้าง project ใหม่สำหรับระบบนี้โดยเฉพาะ
2. ไป SQL Editor > New query วางเนื้อหา schema.sql ทั้งไฟล์ แล้ว Run (สร้างตารางส่วนตัว, RPC, สิทธิ์)
3. ไป Authentication > Users > Add user > Create new user สร้างบัญชีด้วยอีเมลของครูที่ใช้งานจริง ตั้งรหัสผ่านที่รัดกุมและยืนยันอีเมล (Auto Confirm User หากมีตัวเลือก) ตามที่ต้องการ หน้าเว็บจะให้กรอกเฉพาะรหัสผ่าน โดยใช้อีเมลจาก config.js
4. กลับ SQL Editor แล้วรันบรรทัดต่อไปนี้ โดยเปลี่ยน YOUR_ADMIN_EMAIL เป็นอีเมลเดียวกับข้อ 3:

```sql
insert into student_private.admins(user_id)
select id from auth.users where email='YOUR_ADMIN_EMAIL' on conflict do nothing;
```
ตรวจสอบว่าพบบัญชีจริงด้วย `select user_id from student_private.admins;` (ควรได้อย่างน้อย 1 แถว)
5. ปิดการสมัครบัญชีสาธารณะใน Authentication settings (ระบบนี้ไม่ต้องให้นักเรียนสมัครบัญชี)
6. ใน Project Settings / Connect / API Keys คัดลอก Project URL และ publishable key หรือ legacy anon key เท่านั้น ห้ามใช้ secret หรือ service_role key
7. เปิด config.js ด้วย Notepad หรือ VS Code แทนค่า supabaseUrl, supabaseKey และ adminEmail ให้ตรงกับโครงการ บันทึกไฟล์

## 2. GitHub Pages
1. สร้าง repository ใหม่ที่ https://github.com/new เช่น student-profile
2. อัปโหลดเฉพาะ index.html, style.css, app.js, config.js, .nojekyll ไปยัง root ของ repository (ไม่ต้องอัปโหลด schema.sql, รายชื่อจริง, รหัสนักเรียน, คู่มือ หรือไฟล์ CSV จริง)
3. เปิด Settings > Pages > Build and deployment > Deploy from a branch > main > /(root) > Save
4. เปิดลิงก์ GitHub Pages ที่ระบบแสดงหลังเผยแพร่

## 3. ใช้งานผู้ดูแล
- กด “ผู้ดูแลระบบ” แล้วกรอกรหัสผ่านของบัญชีที่สร้างใน Supabase ไม่ต้องกรอกอีเมลในหน้าเว็บ รหัสผ่านไม่ได้อยู่ในไฟล์เว็บ
- ดาวน์โหลดไฟล์ตัวอย่าง CSV หรือนำไฟล์ template.csv ไปเปิดใน Excel กำหนดรหัสนักเรียนและเบอร์โทรเป็นชนิด Text เพื่อรักษาเลข 0 นำหน้า (การเปิด CSV โดยตรงใน Excel อาจทำให้เลข 0 หาย)
- ใช้หัวคอลัมน์ student_id,full_name,room,seat_no เช่น 12345,เด็กชายตัวอย่าง ทดสอบ,401,1 ; seat_no เว้นว่างได้
- บันทึกเป็น CSV UTF-8 แล้วนำเข้าในเมนูจัดการรายชื่อ ระบบปรับข้อมูลตามรหัสนักเรียนโดยคงสถานะเดิม ไม่ลบรายชื่อเก่าที่ไม่อยู่ในไฟล์
- เลือกห้อง ดาวน์โหลดรหัสยืนยันรายบุคคล แล้วแจกเฉพาะเจ้าของรหัสเป็นการส่วนตัว ห้ามเผยแพร่ไฟล์รวม
- เลือกห้อง ดูสถานะ จำนวนผู้ส่ง/ยังไม่ส่ง ค้นหา ดู/บันทึกรูป ดาวน์โหลด CSV หรือพิมพ์รายงาน
- เปิดให้ส่งใหม่จะลบรูปและข้อมูลเดิมของคนที่เลือกจริง ๆ ต้องยืนยันก่อน
- รายงานและรหัสยืนยันเป็นข้อมูลส่วนบุคคล เก็บในที่จำกัดสิทธิ์และอย่าส่งในกลุ่มสาธารณะ

## 4. ใช้งานนักเรียน
กรอกเลขประจำตัวและรหัสยืนยันส่วนตัว > ค้นหา > ตรวจสอบชื่อ > เลือกภาพ JPG/PNG/WebP > กรอกชื่อเล่นและเบอร์โทร 10 หลักขึ้นต้นด้วย 0 > ส่งข้อมูล ระบบจะแสดงสถานะส่งแล้วและไม่ให้ส่งซ้ำ หากครูเปิดให้ส่งใหม่จะสามารถส่งใหม่ได้

### ตัวเลือกใช้เลขประจำตัวอย่างเดียว (ไม่แนะนำ)
ค่าเริ่มต้นต้องใช้รหัสยืนยัน เพื่อไม่ให้ผู้ที่รู้หรือเดารหัสนักเรียนดูชื่อหรือส่งข้อมูลแทนกัน หากต้องการใช้ ID อย่างเดียวจริง ๆ ให้เข้า SQL Editor และรัน:
```sql
update student_private.settings set require_code=false where singleton;
```
รีเฟรชหน้าเว็บ จะไม่แสดงช่องรหัสยืนยัน การตั้งค่านี้ทำให้ใครก็ตามที่รู้หรือเดาเลขประจำตัวสามารถค้นชื่อและส่งแทนได้ จึงไม่ควรเปิดบนเว็บสาธารณะกับข้อมูลนักเรียนจริง หากต้องการคืนความปลอดภัย:
```sql
update student_private.settings set require_code=true where singleton;
```

## 5. ข้อมูลและข้อจำกัด
- ภาพถูกแปลงเป็น JPEG ด้วย Canvas ย่อด้านยาวสุด 1000 px และไม่เกิน 300 KiB ก่อนส่ง (จัดเก็บ base64 ในตาราง Supabase ส่วนตัว ไม่ใช่ public Storage bucket) เหมาะกับงานเก็บรูปขนาดเล็ก; base64 ใช้พื้นที่มากกว่าภาพจริงประมาณหนึ่งในสาม ตรวจสอบโควตาฐานข้อมูลก่อนนำเข้าเป็นจำนวนมาก
- นักเรียนที่ยืนยันตัวตนจะเห็นแค่ชื่อ ห้อง และสถานะ ไม่สามารถอ่านเบอร์/รูปจาก RPC นักเรียน; ผู้ดูแลผ่าน Supabase Auth และตรวจ allowlist ฝั่งฐานข้อมูลทุกครั้ง
- รูปภาพและเบอร์โทรเป็นข้อมูลส่วนบุคคลของนักเรียน ควรแจ้งวัตถุประสงค์ ระยะเวลาเก็บข้อมูล ผู้มีสิทธิ์เข้าถึง และช่องทางขอแก้ไข/ลบ ให้สอดคล้องกับแนวปฏิบัติของโรงเรียนก่อนเปิดใช้จริง
- ไม่ฝังรหัสผ่านที่แจ้งไว้ใน GitHub หรือ SQL และแนะนำให้ใช้รหัสใหม่ที่คาดเดายาก ไม่ใช่เบอร์โทรศัพท์
- หากใช้กับโรงเรียนหลายพันคนหรือเปิดสาธารณะวงกว้าง ควรเพิ่ม server-side rate limiting/CAPTCHA และพิจารณา Private Storage สำหรับรูป ยังไม่ได้รวมไว้ในรุ่นนี้
- หากต้องลบทั้งข้อมูลของนักเรียนรายหนึ่ง ผู้ดูแลโครงการ Supabase สามารถลบจาก student_private.students ใน SQL Editor (ข้อมูลการส่งจะถูกลบด้วย cascade) ตรวจสอบรหัสก่อนลบ
- ไฟล์นี้ผ่านการตรวจ syntax JavaScript แล้ว แต่ยังไม่ได้เชื่อมกับ Supabase/GitHub ของจริง จึงต้องทดสอบด้วยรายชื่อสมมติก่อนนำข้อมูลนักเรียนจริงเข้า

## 6. ทดสอบก่อนเปิดใช้
- นำเข้ารายชื่อสมมติ 2 คนคนละห้อง ตรวจรายงานยังไม่ส่ง
- รหัสผิดต้องค้นหาไม่พบ รหัสถูกต้องเห็นชื่อ/ห้อง
- ส่งรูปพร้อมข้อมูล ตรวจขึ้นส่งแล้วเมื่อค้นหาใหม่ และส่งซ้ำไม่ได้
- ตรวจรายงานรายห้อง เปิดรูป/ดาวน์โหลด CSV พิมพ์รายงาน และเปิดให้ส่งใหม่
- ทดสอบใน browser ที่ไม่ได้ล็อกอิน: ต้องไม่เรียก sp_admin_report หรือ sp_admin_photo ได้
- ทดสอบบน Android/iOS ด้วย HTTPS GitHub Pages
